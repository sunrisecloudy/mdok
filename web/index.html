A five-minute start

Build it.
Run it.

MDOK ships as a Rust CLI. No editor plugin, hosted runner, or JavaScript build step is required to start from this repository.

01

Build from source

Clone the project, then compile the release CLI.

$ cargo build --release
$ cargo run -p mdok-cli -- lint \
  mdok-prd/examples/auth-flow.md
02

Plan before the network

Inspect a normalized, redacted plan.

$ cargo run -p mdok-cli -- plan api.mdok.md \
  --var base_url=http://127.0.0.1:9800
  • ✓ no request sent by lint
  • ✓ variables stay typed
  • ✓ secrets stay redacted
03

Test the workflow

Run the document, then choose the report your CI needs.

$ cargo run -p mdok-cli -- test api.mdok.md \
  --json
human--json--json-lines--junit

Prefer a local fixture? mdok-test-server --listen 127.0.0.1:0 --json-ready provides deterministic HTTP fixtures for examples and integration tests.

# Authentication flow

```toml mdok vars
base_url = "http://127.0.0.1:9800"
email = "agent@example.com"
```

```curl mdok name=login
curl --request POST "{{base_url}}/auth/login"
  --header "Content-Type: application/json"
```

```jmespath mdok check=login
status == `200`
type(body.access_token) == 'string'
```
↳Capture and continue{access_token, user_id} become typed variables for the next request.

# User CRUD flow

```curl mdok name=create
curl --request POST "{{base_url}}/users"
  --data-raw '{"name":"Ada"}'
```

```jmespath mdok check=create
status == `201`
body.name == 'Ada'
```

```jmespath mdok capture=create
{user_id: body.id}
```
↳Capture and continueUse {{user_id|url}} safely in the read request.
