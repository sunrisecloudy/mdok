How it works

Paste the curl.
Add the proof.

Your API examples already live in Markdown. mdok makes them executable — no new HTTP DSL to learn.

what docs give youcurl
curl --request POST \
  --header "Content-Type: application/json" \
  --data-raw '{"email":"agent@example.com"}' \
  "http://127.0.0.1:9800/auth/login"
+
what mdok runsauth-flow.md
```curl mdok name=login
curl --request POST "{{base_url}}/auth/login"
  --data-raw '{"email":{{email|json}}}'
```

```jmespath mdok check=login
status == `200`
body.user.email == variables.email
```

```jmespath mdok capture=login
{token: body.access_token}
```

Captures publish only after their checks pass, so the next request always builds on verified data. See the full example ↗

Features

Everything else,
already handled.

Checks & captures

Standard JMESPath against structured results. Assert status and body, then pass typed values to the next request.

MCP server

One local stdio server exposes test, lint, plan, list, probe, import, and version to any agent.

MCP guide ↗

Postman import

Convert Collection v2.1 to reviewable Markdown with a provenance manifest. Unsupported semantics are reported, never dropped.

Import boundary ↗

Reports for anything

Human output at the terminal, or JSON, JSON Lines, and JUnit for the pipeline you already run.
